How PowerMonger paints its terrain

The island has no texture map and no flat colours. Every triangle carries one number, and that number selects a 16 by 16 stipple tile. The screen position picks the pixel inside the tile. This page is built from the game's own RAM: the pattern table is the real one, and each picture below is rebuilt from it and checked against the game's frame buffer.

The rule
pixel(x, y) = tile[colourByte][(y + phase/8) mod 16][x mod 16]
colourByte
the colour byte of the triangle (colour plane A at +0 or colour plane B at -8257 of $438ee: a slope shade built from the altitude plane), +tick if below 12, or 0x1c if forced
table
16 KB at $2e000: 128 bytes per colour byte = 16 rows of 8 bytes = one 16x16 tile of 4-bit pixels
checked
loading

2. The steps behind the panel

  1. The cell. The 8 by 8 window of the map is projected to screen corners. Each cell is split into two triangles. The cell's flag byte, bit 7, picks which diagonal splits it. The two triangles are drawn far to near, so nearer ones overwrite farther ones.
  2. The colour byte. One triangle of the cell takes the cell's type byte, the other takes its height byte. Inland the two differ by a few steps, which is the two-tone split you see on slopes. A byte below 12 is water and gets the water tick (0 to 3) added, which makes the sea shimmer.
  3. The forced colour. Before filling, the game orders the triangle's vertices by screen height. If the middle one is on the left, the triangle is wound the other way round, which in practice means it faces away from the eye. The game then ignores the terrain byte and uses 0x1c forced.
  4. The slot. The table starts at $2e000. A colour byte owns 128 bytes from there. No terrain cell ever holds byte 0x1c itself, so that slot exists only for the forced rule.
  5. The row. The 128 bytes are 16 rows of 8 bytes. Scanline y reads row (y + phase/8) mod 16. The game advances its read pointer by 8 bytes per scanline and lets the low byte wrap, which is where the mod comes from. The phase is 0 or 64 bytes; it flips every time the camera moves and the grid is re-projected.
  6. The 16 pixels. The 8 bytes are two longwords. The first holds bit planes 0 and 1, the second planes 2 and 3. Pixel column x mod 16 is bit 15 - (x mod 16) of each of the four 16-bit words, and those four bits form a palette index 0 to 15. The fill loop repeats the same 16 pixels along the whole span of the scanline.

3. Every tile the terrain can use

Click a tile to light up, in the preview, every pixel that came from it. The number under a tile is how many pixels of the selected scene it paints. The coloured bar shows the palette mix of the tile. The four sea tiles are the water shimmer: drag Water tick in section 1 and the sea swaps between them. The counter advances once per simulation tick, so the sea repeats every four ticks.

4. The tiles are dither ramps

Colour byte is also brightness. Along the terrain, byte rises with height, so the table is a set of ramps: each step swaps about an eighth of the tile's pixels from one palette colour to the next. The ramps are built in two different ways.

Rock ramp, bytes 0x0c to 0x1b: one fixed threshold map

Each pixel has a rank: the first slot of the ramp at which it switches to the next colour. The same map drives both halves (colour 1 to 2, then 2 to 3), and each slot's set of switched pixels contains the previous one's.

Grass ramp, bytes 0x1f to 0x2d: five scatters, not nested

Five fixed scatters of 32, 80, 128, 192 and 224 pixels, and they are not nested: a denser one does not contain the sparser one. The same five are reused for each colour pair (13 over 1, 12 over 13, 11 over 12). The table compares neighbours: how many pixels of the first scatter are still set in the next, against what two independent scatters of those densities would share.

5. The four seasons rewrite part of the table

Slots 0x1d to 0x2e are a working copy. The table also stores three finished versions of those 18 slots. When the season changes, the game copies 16 pixels per tick from the new version into the live slots, visiting them in the order of a 13-bit linear congruential sequence. A full change takes 8191 steps, about 512 ticks. Drag the slider to freeze the change part-way.

The autumn table is the spring table: the game uses the same source for both. Bytes 0x2f and above are not replaced, so high ground keeps the same colours in every season; its slots are also the stored summer table.
