# Game learning: map of the field

A reading map of research on learning to play video games, grouped by direction, with what each direction means for this repo. The same tree is drawn in [field-map.canvas](field-map.canvas) (Obsidian Canvas; the repo root is the vault). Both files are generated by `build_map.py` from one table: edit that, not these.

Whether this emulator can be trusted as the judge of a game model is tested against a second emulator in [hatari_oracle.md](hatari_oracle.md): eight Virus routines run on Hatari's CPU from this emulator's state, 24/24 calls equal in RAM and registers (`py/gate_hatari_callcap.sh`), and a whole Virus demo flight run on Hatari from the same start state agrees at 11,782/11,782 ticks (`py/gate_hatari_game.sh full`).

Papers were found through OpenAlex title and semantic searches. Citation counts are OpenAlex's on 2026-11-18. The **basis** column says where each one-line description comes from: **A** the abstract OpenAlex returned, **F** the full text, **T** the title alone, **R** a detail recalled from memory and not checked against the paper (marked `(R)` in the line). Only the papers marked F were read in full.

## Learning to play games

A game is a Markov decision process: state, action, transition rule, reward. The research splits on where the transition rule comes from (an emulator, extracted code, or a learned network) and on how many game steps the learner may spend.

The tree:

- **Environments and evaluation**: Arcade Learning Environment, Revisiting the ALE, Gotta Learn Fast (Gym Retro), Survey: deep RL in video games, Statistical precipice, Atari-5, OCAtari, Gymnasium
- **Model-free learning**: DQN, PPO, Rainbow, IMPALA, R2D2, Agent57, BBF, PQN (Simplifying deep TD), Discovered RL rule
- **Search with a model**: AlphaZero, MuZero, EfficientZero, EfficientZero V2
- **Learned world models**: World Models, SimPLe, DreamerV2, IRIS, STORM, TD-MPC2, Delta-IRIS, DreamerV3, Dreamer 4, Simulus
- **Neural game engines**: Genie, GameNGen
- **Exploration, imitation, privileged teachers**: DAgger, Evolution Strategies, Go-Explore, First return, then explore, Learning by Cheating, Decision Transformer, VPT
- **Throughput: fast and parallel simulators**: CuLE, Sample Factory, Brax, EnvPool, Jumanji, Craftax, PufferLib, Pokemon Red via RL
- **Successes at scale**: AlphaStar, OpenAI Five, GT Sophy, DeepNash
- **Language-model agents**: Gato, SIMA, Survey: LLM game agents, BALROG, lmgame-Bench, SIMA 2, AutoHarness
- **Code world models**
  - **Heritage: rules as programs**: VGDL, Schema Networks, Theory-based RL (EMPA), AutumnSynth
  - **A language model writes the model**: ByteSized32, WorldCoder, Code world models + MCTS, WALL-E, CWM for general game playing, TheoryCoder (bilevel planning), Symbolic models, test-time scaling, Finite Automata Extraction, OPINE-World, Executable models for ARC-AGI-3, Mind-Studio, PatchWorld, Distilling CWM generation, Coding agent as world brain
  - **Is the model right?**: Text2World, When a verified world model still loses
  - **From the binary**: LLM4Decompile, Super Mario Odyssey by decompilation
  - **Adjacent: programs as policies and goals**: PIRL, Code as Policies, Goals as reward-producing programs

## Code world models

The game's rules written as an executable program, which a classical planner (tree search, model-predictive control) then searches. The program is exact where it is right, fast, and readable, unlike a learned network.

**For this repo** (inferred, nothing built): This is what reversing/<game>/py already holds. The field infers the program from play or from a rules text; this repo extracts it from the 68000 and gates it against the emulator. One paper does the same from a binary (Super Mario Odyssey, below).

### Is the model right?

How a synthesised model is accepted, and what a passing check does not show.

**For this repo** (inferred, nothing built): The gates here are match counts on captured calls and frames (2,346 of 2,346 arrivals), the 'sampling gate' the 2026 paper warns about: a rule that fires rarely can be absent from the sample. Its remedy is to test on the states the planner visits, or by play; here that means gating a port on whole recorded games flown by the pilot. Reading the code instead of inferring it is the other defence, and the repo has it.

| Paper | Year | Venue | Cited | Basis | What it is |
|---|---|---|---|---|---|
| [Text2World](https://openalex.org/W4412944538) | 2025 | ACL Findings | 50 | A | Benchmark for language-model generation of symbolic (PDDL) world models, built to fix indirect and noisy evaluation. |
| [When a verified world model still loses](https://openalex.org/W7169534322) * | 2026 | arXiv | 5 | A | A model at 100% sampled transition accuracy still loses at play: the under-1% it gets wrong is the pivotal rule. More data did not fix it; adequacy should be measured on the search distribution or by play. |

### From the binary

The program is recovered from the shipped game instead of inferred from its behaviour.

**For this repo** (inferred, nothing built): The direct precedent for this repo, and prior art for any post on it. Its simulator is the game's own code, decompiled to C++ on top of a community project and a release that shipped with symbols, then recompiled natively; here the code stays in the emulator and each routine gets a separate model. It has two checks. A function 'matches' when recompiling it with the game's compiler gives the same machine code, a proof for every input that hand-written 68000 has no equivalent of; most functions are only 'functional', checked by watching behaviour. End to end, 13 scripted moves are replayed on console and simulator and the position compared: 8 agree, 5 drift. The callcap gates here compare all touched memory on thousands of calls, which is finer, but nothing here yet replays whole inputs through a composed port, the test that caught their drift. Speed: 84,000 to 144,000 frames/s compiled with optimisation, against 60 on the console, falling to 363 to 9,993 once observations are sent to Python.

| Paper | Year | Venue | Cited | Basis | What it is |
|---|---|---|---|---|---|
| [LLM4Decompile](https://openalex.org/W4404783570) | 2024 | EMNLP | 220 | A | Open language models trained to decompile binary code, motivated by Ghidra output being hard to read and execute. |
| [Super Mario Odyssey by decompilation](https://openalex.org/W7233756573) * | 2026 | IEEE CoG | 0 | F | The player-movement and collision code decompiled to C++ and recompiled natively as a simulator (no enemies, camera or damage); 8 of 13 scripted moves reproduce the console's positions; a PPO agent trained in it is moved back to the console on one stage. |
