## Known traps

- **Chained `bp` commands each continue from the previous stop**: `bp 661a`, `w ...`, `bp 6638 3000`, `bp 66a4 3000` spends 3000 steps in the first, so the second looks at a path that already ran. After a poke use one `hits <n> <addrs>` over everything of interest (the 144th pass lost a run to this).
- **`arm_census.py` forces the state to 6**: `$68fe` answers "none" for a group in state 8 or `$d` whose best lord is already its target, so `_decide` on a marching group reads as the transfer arm (23 false 'xfer' groups before the state was forced).
- **`census_8a.py` takes a file of snapshot paths, not paths**; `tree_census.py`'s "on byte6 8" is a cell match, not record identity.
- **`PAGES0=1` is an environment variable of `build_land.sh` and `build_series.py`**; a seed `k` makes a different land on each roll, so give each roll its own output directory. `sweep.sh` built k = 0, 4, .., 140, 143 only: lands 5 and 25 were built separately.
- **`runland.sh` names `<name>_s1..s4` are the ends of the stretches**, so a `hits` census started from `<name>_s1` begins 50M steps into the run, while `capture_hits.py` counts hits from whatever start snapshot it is given: take natural entries from the land's own start snapshot with the hit numbers of the census run on that same snapshot.
- **`gate_orders.py` takes natural entries from `nat/n<addr>_<anything>.json`**: the part of the file stem before the first underscore must be `n` plus the routine's address (the target is looked up from it).
- **`census.py`'s old address list lacked `$3154`, `$3248`, `$38ce`, `$6128`, `$5fa0`**: a preview-roll census file with no line for them says nothing; only the `hits` lines with a count do.
- **`callcap` outcome `THREW ... WriteEa: immediate operand is not a valid destination`** is a runaway, not an emulator bug: four synthetic `fsm15` states throw it and are the "5 unrun".
- **A model gate caches callcap JSON**: a `reuse` run keeps stale deltas; delete the state's JSON or run without `reuse`.
- **`bpc <addr> <n> <max>` counts hits from the start snapshot, and `max` bounds the whole gap** (`capture_hits.py --max` defaults to 50M; pages-0 land captures needed `--max 30000000`, the preview roll `4000000`). A hit it does not reach still leaves a `.snap` with no `.ram`: filter on `.ram`. **`bpc` gives up after 200000 steps by default**.
- **`gate_coverage.py` counts a cite, not an execution**: `$15c46` runs in the fsm15 gate through mode `$5a` and still lists as ungated.
- **Transcribe from the listing, not from a similar neighbour**; **a failure branch that always follows another failure is a clue**; **`add.w`/`subi.w` + `bge/blt` test N xor V**, so a wrapped word's sign is wrong.
- **macOS `seq -s,` leaves a trailing comma**; **the Edit tool drops trailing spaces from `new_string`**; **bucket links of records below `$51b66` are negative 16-bit offsets** (`_objaddr`); `snap_render.py` shows the shifter base at the snapshot.
- A subagent audit of docs finds real contradictions and invents none so far, but spot check one claim per agent.
- Earlier traps still apply: a routine's tail that ends in the iterator's `bra $1622c` cannot be `callcap`ed in place; REPL `w` takes longwords at even addresses; entity records are the first 512 only; one entity tick is ~200k steps; `py/clicks.py` pointer moves 1:1; do not reopen the SingleStepTests track or `$4342`'s 8 proven branches; a full `pm_export.py` rerun regresses `entities.json`.
